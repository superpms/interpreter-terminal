# Runtime Chain

The terminal runtime is a small chain of interpreter resolution, command resolution, sandbox creation, injection, and command execution.

## Entry Class

`pms\interpreter\terminal\Interpreter` extends `pms\app\InterpreterApp` and exposes `public static function entry(): mixed`.

Its entry method:

1. Registers a `SystemErrorBroadcast` listener that rethrows stored framework errors.
2. Calls `TerminalCommandHook::run()`.
3. Catches only `CliModeForcedInterruptException` as the terminal `dd()` interruption protocol.
4. Rethrows every other throwable.

For `dd()` interruption, it exits with a red `dd(...) Forced Interrupt!` message generated by `CommandOutput::setColorStr()`.

## Command Registry Resolution

`TerminalCommandHook::run()` performs command lookup:

1. Runs `TerminalLifecycleHook::run(LIFECYCLE_BOOT)`.
2. Reads `$_SERVER['argv']` and drops the PHP script name.
3. Exits with `未输入要执行的命令` if no command name is present.
4. Merges the static command container with `config('command', [])`.
5. Uses the first argv item as the command name.
6. Exits if the command name is missing or if the mapped class does not exist.
7. Runs `TerminalLifecycleHook::run(LIFECYCLE_BOOTED, $name, $argv, $namespace)`.
8. Creates `new Sandbox($commandList, $name, $argv)` and runs the resolved class.

The merge order is:

```php
static::$container = [
    ...static::$container,
    ...config('command', []),
];
```

So command mappings from `config('command')` are part of the final runtime command table.

## Sandbox Execution

`pms\interpreter\terminal\Sandbox` extends the framework container and is responsible for creating the command instance.

The sandbox sequence is:

1. Run `LIFECYCLE_SANDBOX_CREATED` with command name, argv, and command list.
2. Reflect the command class.
3. Read the command class default `validate` property.
4. Put `TerminalInputInject::class` into the container as `new CommandInput($validate)`.
5. Put `TerminalOutputInject::class` into the container as `CommandOutput::class`.
6. Run `LIFECYCLE_SANDBOX_BOOT`.
7. Instantiate the command class with constructor arguments `$commandList` and `$argv`.
8. Run property attribute injection through the base container.
9. Run `LIFECYCLE_SANDBOX_BOOTED`.
10. Call `$obj->entry()`.
11. Run `LIFECYCLE_SANDBOX_RAN`.
12. On sandbox destruction, run `LIFECYCLE_SANDBOX_DESTRUCT`.

## Constructor Contract

`TerminalCommandApp` has a final constructor:

```php
final public function __construct(protected array $commandList, protected array $argv) {}
```

Command classes should not replace this constructor. Put command behavior in `entry()` or in methods called by `entry()`.

## Lifecycle Arguments

The package passes different context to each lifecycle:

- `LIFECYCLE_BOOT`: no extra args
- `LIFECYCLE_BOOTED`: command name, argv, command class
- `LIFECYCLE_SANDBOX_CREATED`: command name, argv, command list
- `LIFECYCLE_SANDBOX_BOOT`: command name, argv, command list, reflected class
- `LIFECYCLE_SANDBOX_BOOTED`: command name, argv, command list, reflected class, command object
- `LIFECYCLE_SANDBOX_RAN`: command name, argv, command list, reflected class, command object
- `LIFECYCLE_SANDBOX_DESTRUCT`: no extra args
